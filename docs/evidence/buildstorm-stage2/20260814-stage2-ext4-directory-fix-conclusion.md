## Root cause fixed

Host QMP samples from the exact production ELF held CPU0 at
`ext4_rs::Ext4::try_insert_to_existing_block`, on the instruction generated by
`if de.unused() { continue; }`.  `dir_remove_entry` legally leaves an unused
first directory record (`inode == 0`), so the loop never advanced while holding
the ext4 lock.  Another CPU spun on that lock and the remaining CPUs idled.

The production fix validates each ext4 record (`rec_len >= 8`, aligned, within
the block and compatible with `name_len`), advances past an undersized unused
record, reuses a large unused record, and propagates malformed-record `EIO`
instead of treating it as `ENOSPC`.  Insertion now writes only the on-disk
record bytes, avoiding the old 264-byte Rust struct copy over a successor.

## Focused and cross-architecture gates

Four focused block-level tests pass: reuse of an unused first record, advance
past an undersized record, zero-length rejection, and occupied-record split
without successor overwrite.  The vendor's unrelated historical extent
binary-search test still fails when the full vendor suite is run.

RISC-V64 and LoongArch64 production/diagnostics release builds pass.  Both
architectures pass the SMP8 resident, high-arena and user-memory lifecycle
regressions, ASID/TLB isolation and 160-MiB heap stress (`capability-pass`).
