# 2026 任务驱动拿分与真机门禁

## 不可突破的规则边界

- 只实现可被普通用户程序复用的内核能力，不按测试名、命令文本或期望答案分支。
- 时间、CPU、内存、网络连接和磁盘容量必须来自硬件描述或内核实时状态。
- 不伪造 `/proc/uptime`、时钟推进或基准耗时；回归脚本只负责调用公开接口并判断结果。
- QEMU 使用快照和临时注入脚本，主测试镜像不写入专用答案。

## 阶段 1：CAgent 公共语义（当前阶段）

目标是一次完善进程调度、时间、文件系统、系统信息和网络观测面，而不是逐题打补丁。

完成门禁：

- 10!、100 天前星期、在线 CPU 数、内核版本。
- TCP 连接计数、创建并核对文件、读写求和、目录计数、磁盘占用、全盘查找脚本。
- RISC-V QEMU 黑盒 10/10；RISC-V 与 LoongArch64 release 编译通过。
- `/proc` 数据随内核状态刷新；在线 CPU 暂时如实报告 1，不冒充 SMP。

遗留门禁：LoongArch64 QEMU 当前到达调度器后未进入首个用户态 shell。进入下一阶段前，先修复首切换并复跑相同 10 项。

## 后续拿分顺序

1. 修复 LoongArch64 用户态首切换，建立双架构 CAgent 10/10 基线。
2. 以 BuildStorm 驱动 `fork/exec/wait4`、并发文件创建、页表复制和回收；先正确，再优化吞吐。
3. 以 LTP 聚类推进 syscall、信号、线程/futex、虚存、VFS 和网络，不按单个 case 写特判。
4. 在正确性门禁稳定后再做 UnixBench/lmbench/iozone 性能优化；任何计时项均使用真实单调时钟。

每一阶段都必须同时满足：上一阶段不回退、双架构编译、QEMU 黑盒、真机最小启动门禁。

## VisionFive 2 真机路线

硬件基线按 StarFive JH7110（4×U74）维护，不按 FU740 假设开发。

1. 固化官方 U-Boot/OpenSBI 启动链、内核装载地址、真实 DTB 保存方式和串口日志采集。
2. 用 DT 驱动内存、hart、时钟、PLIC、UART 和根存储发现；QEMU 地址不得成为板级默认值。
3. 先完成单核串口 + SD/eMMC 根文件系统 + RTC/真实时间，再启用多 hart。
4. SMP 上线前补齐每 CPU 状态、IPI、TLB shootdown、锁和中断亲和；上线后才把 online CPU 从 1 提升为实际值。
5. 网络、USB、PCIe/HDMI 依次按可测试工作负载接入，驱动失败不得影响基础启动。

真机最小门禁：冷启动 20 次、连续运行 CAgent 10 次、文件系统断电恢复检查、4 hart 压力运行、串口日志可复现。

## 龙芯 2K1000LA 真机路线

1. 固化板载固件的内核入口、DT/启动参数、串口、内存窗口及 LoongArch LA264 工具链参数。
2. 优先解决当前 QEMU 首个用户任务切换问题，并把相同修复带入真机异常入口、页表和返回用户态路径。
3. 接入恒定时钟/定时器、中断控制器、UART 和根块设备；真实时间不可用时明确降级，不伪造当前日期。
4. 完成双核启动、IOCSR/IPI、跨核 TLB 刷新后，再报告 2 个在线 CPU。
5. 依次接入板载 SATA/存储、双千兆网、USB 和 PCIe；每个驱动都有超时与失败隔离。

真机最小门禁与 VisionFive 2 相同，并额外要求双核启动/关闭循环和 PCIe/双网口中断压力测试。
