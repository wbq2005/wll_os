### 1.2 表 B：相对 basic 样例的缺口（测点 → ABI → 分发器）

**信息来源**：样例仓库中 [`oscomp_syscalls.md`](../_tmp/testsuits-pre-2025/oscomp_syscalls.md)（RISC-V ABI：`a7`=调用号）、[`basic/user/lib/syscall.c`](../_tmp/testsuits-pre-2025/basic/user/lib/syscall.c)（libc 如何封装 `fork`/`open`/`pipe`/`dup2`/`sleep` 等）、[`basic/user/src/oscomp/run-all.sh`](../_tmp/testsuits-pre-2025/basic/user/src/oscomp/run-all.sh)（35 个测点枚举）。

**说明**：

- 测点名（如 `mkdir_`）多为 **可执行文件名**，实现侧对应 `mkdir` → `mkdirat`。
- `fork()` 在样例中为 `syscall(SYS_clone, SIGCHLD, 0)`；`clone()` 测点通过 `__clone` 走 **完整 6 参风格** 的 `clone`（见 `basic/user/lib/arch/riscv/clone.s`）。内核需在同一 `clone` 入口兼容 **fork 形态** 与 **带栈线程/子进程形态**。
- `open` → `openat(AT_FDCWD, …)`；`pipe` → `pipe2(fd, 0)`；`dup2` → `dup3(old, new, 0)`；`sleep` → `nanosleep`；`wait`/`waitpid` → `wait4`。

### 2.5 非 basic 但 P1+（避免与 P0 混淆）

- **linkat**：样例 libc 提供 `link`/`sys_linkat`，busybox/文件操作可能依赖；basic 表 B 未单独列「link」测点，但宜与 `unlinkat` 同级规划。
- **mprotect / mmap 高级语义**：性能测例、完整 libc 常需要；basic 未单列但属于 syscall 常量表中长期项。
- **信号集**：`sigaction`、`sigprocmask`、`kill` 等——cyclictest / 部分 ltp；`signal.rs` 需并入分发器。
- **shutdown / reboot**：评测要求跑完测例后 **主动关机使 QEMU 退出**（见 §2.6）；与 socket 的 `shutdown` 不同概念，文档与实现命名注意区分。

### 2.6 样例执行与日志门禁（评测流程）

以下内容摘自赛题样例 [`README.md`](../_tmp/testsuits-pre-2025/README.md)（2025 赛题表述；2026 若有更新以官方最新仓库为准），用于约束 **「能跑」与「能得分」** 的差异。

**提交物**

- 项目根目录 `Makefile` 的 `all` 目标须能编译出 **`kernel-rv` 与 `kernel-la`**（ELF）。
- 可选生成 **`disk.img` / `disk-la.img`**；评测 QEMU 若提供该参数则挂载第二块盘。

**评测时磁盘与文件系统**

- QEMU 使用 `-drive` 挂载 **ext4、无分区表** 的镜像；镜像根目录含预编译 ELF 与 **`xxxxx_testcode.sh`** 测试脚本。
- 内核启动后应 **扫描磁盘并串行执行** 各测试脚本，将结果输出到 **串口/控制台**；**不得并行**跑多个脚本。
- 若跳过某些脚本，该测点不得分；但若模拟脚本行为，仍须输出规定格式（见下），否则影响评分。

**必须输出的格式**

- 每个测试组前后须输出类似：  
  `#### OS COMP TEST GROUP START basic ####`  
  `#### OS COMP TEST GROUP END basic ####`  
  （`basic` 为组名占位；具体字符串以当年官方说明为准。）

**结束条件**

- 全部测例执行结束后，内核应 **主动关机**，使 QEMU 进程退出；评测方在进程退出或超时后打分。

**QEMU 命令形态（摘要）**

- RISC-V：`qemu-system-riscv64 -machine virt -kernel {kernel-rv} -m {mem} -nographic -smp {smp} -bios default`，挂载 `virtio-blk` 等（完整参数见样例 README）。
- LoongArch：`qemu-system-loongarch64 -kernel {kernel-la} ...`，块设备多为 **PCI** 形态。

```mermaid
flowchart LR
  boot[内核启动] --> mount[识别 virtio 盘与 ext4]
  mount --> scan[扫描根目录脚本]
  scan --> bannerStart[输出 GROUP START]
  bannerStart --> run[串行执行单测脚本]
  run --> bannerEnd[输出 GROUP END]
  bannerEnd --> shutdown[关机退出 QEMU]
```

## 四、关键技术实现优先级

### 高优先级 (必须完成)

1. **clone + fork 语义**（同一调用号）：basic 多测依赖，优先级高于单纯「调度优化」。
2. **pipe2 + fd 表协同**：pipe 测点与 shell 管道基础。
3. **open/read/write + 文件系统路径**：MemFS 迭代与 ext4 评测轨并行规划。
4. **mmap/brk + 缺页/回收**：与 execve、用户堆增长强相关。

### 中优先级

1. **linkat / fcntl / mprotect**：libc 与 busybox 扩展。
2. **信号**：cyclictest / 部分高级测例。
3. **时间与计时**：`nanosleep` / `gettimeofday` 已接线，持续对齐精度与 errno。

### 低优先级

1. **网络协议栈与 socket**：iperf/netperf。
2. **SMP**：性能加分项。

## 五、双架构支持策略

### 5.1 架构差异处理

| 特性 | RISC-V | LoongArch |
|------|--------|-----------|
| VirtIO 传输 | MMIO (`virtio-mmio-bus`) | 常为 **PCI**（`virtio-blk-pci`） |
| 块设备 | 固定 MMIO 区域（见赛题 QEMU 参数） | PCI 枚举发现 |
| 链接脚本 | `linker_riscv64.lds`（以仓库为准） | `linker_loongarch64.lds` |
| 目标三元组 | `riscv64gc-unknown-none-elf` | `loongarch64-unknown-none` |

本地验证命令可与 [`README.md`](../README.md) 中 QEMU 行对齐；**评测参数以样例 README 全文为准**。

### 5.2 条件编译示例

```rust

#[cfg(target_arch = "loongarch64")]
```
